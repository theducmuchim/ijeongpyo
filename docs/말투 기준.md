# 이정표 말투 기준

앱, 소개 사이트, AI가 쓰는 안내 문장에 모두 같은 기준을 쓴다. `npm run tone`으로 어긋난 곳을 찾는다.
AI 지시문의 말투 규칙은 `lib/prompts.ts`의 `TONE`, AI 답을 마지막으로 거르는 규칙은 `lib/tone.ts`에 있다.

## 참고한 기준

| 어디 | 가져온 것 |
|---|---|
| 토스 라이팅 원칙 8가지 | 다음 화면을 짐작할 수 있게(Predictable hint), 군더더기 빼기(Weed cutting), 빈 문장 빼기, 핵심 하나만, 쉬운 말, 강요보다 제안, 모두에게 무해한 말, 숨은 감정 살피기 |
| 토스 디자인 시스템(TDS) 문구 규칙 | 시트 제목은 한 줄, 버튼 하나면 '~하기', 다음 화면으로 넘기면 '확인'·'다음', 버튼 둘이면 '취소' 대신 '닫기'·'다음에' |
| 디지털 정부 서비스 UX 라이팅 가이드 | 명확하게·간결하게·일관되게·배려하며·정확하게. 어려운 말은 쉬운 말로("내구연한" → "사용 가능 햇수"). '~할 것'처럼 명사로 끝내는 명령조는 피하기. 선택지만 읽어도 뜻이 통하게("예/아니오" 대신 "동의함/동의 안 함") |
| 마이크로카피 일반 원칙 | 버튼은 누르면 일어나는 일의 이름. 오류는 무슨 일인지와 할 일. 빈 화면은 왜 비었는지와 다음 행동 |

공공 서비스 가이드는 하십시오체를 쓰지만, 이정표는 한 사람이 혼자 쓰는 앱이라 토스·당근·카카오뱅크처럼 해요체를 쓴다.

## 이정표만의 원칙

1. **안내판처럼 담담하게.** 위로, 칭찬, 감탄, 사과, 느낌표, 이모지를 쓰지 않는다. 길을 잃은 상황을 극적으로 말하지 않는다.
   토스의 '숨은 감정 살피기'는 달래는 말이 아니라, 지금 할 일을 하나만 주는 것으로 지킨다.
2. **길안내가 목적, 학습은 안내 방식.** 훈련, 치료, 개선 효과를 약속하지 않는다.
3. **눈에 보이는 것으로.** 동서남북, 거리 숫자 대신 간판과 건물로 말한다.
4. **조사는 받침에 맞게.** `lib/josa.ts`의 `josa()`를 쓴다. "을(를)"처럼 쓰지 않는다.

5. **말하듯 이어서.** 짧은 문장을 끊어 나열하지 않고, 사람이 옆에서 설명하듯 이어 쓴다.
   - "사진 한 장과 메모를 남기면 AI가 안내 카드로 만들어요" → "사진 한 장과 메모를 남기면, AI가 그걸로 안내 카드를 만들어 줘요"
   - "출발지는 지금 위치예요" → "지금 서 있는 곳에서 출발해요"
   - "화면을 끄지 마세요" → "그동안 화면을 켜 두세요" (하지 말라는 말보다 할 일)
   - 같은 낱말이 한 문장에 두 번 나오지 않게 ("AI 대신 … AI를 부르지 않아요" → 한 번만)

## 끝맺음

| 쓰임 | 끝 | 예 |
|---|---|---|
| 길 안내 문장(카드) | ~세요 | 꽃집에서 왼쪽으로 가세요 |
| 사용자에게 부탁 | ~해 주세요 | 간판이 보이게 찍어 주세요 |
| 설명, 상태, 결과 | ~해요 / ~이에요 / ~했어요 | 카드를 바꿨어요 |
| 버튼 | 동사 '~하기' 또는 짧은 동작 | 이 길로 가기, 다시 찍기, 저장하기 |
| 진행 중 | ~하는 중(…) | 위치 찾는 중 |
| 정보 라벨 | 명사 | 오늘 걸음, 카드 4장 |
| 안전 | ~하세요 (그대로 둔다) | 신호를 직접 확인하세요 |

예외: 도움 요청 화면은 지나가는 사람이 읽으므로 "고맙습니다"를 쓴다.

쓰지 않는 끝: ~습니다, ~하십시오, ~할 것, ~바랍니다, ~볼까요?, ~하시겠어요?

## 버튼과 확인 창

- 버튼 이름만 읽어도 무슨 일이 일어나는지 알게 쓴다. "확인"은 안내를 읽고 닫을 때만 쓴다.
- 확인 창: 제목은 질문 한 줄("이 길을 지울까요?"), 본문은 결과("되돌릴 수 없어요"), 버튼은 동작("지우기") + "닫기".
- 대답 버튼은 질문 없이도 뜻이 통하게: "보여요 / 안 보여요".

## 오류와 빈 화면

- 오류: 무슨 일인지 + 할 일. "이 길을 찾을 수 없어요. 홈에서 길을 다시 골라 주세요."
- 서버 오류를 화면에서 다른 안내와 이을 때는 첫 문장만 쓴다(새 길 등록의 `firstSentence`).
- 개발 용어(요청, 응답 코드, 키 이름)는 화면에 내지 않는다. 원인이 꼭 필요하면 괄호에 짧게 붙인다.
- 빈 화면: 왜 비었는지 + 다음 행동. "찾는 장소가 없어요. 다른 이름으로 검색해 보세요."

## 같은 것은 같은 말로

| 쓰는 말 | 안 쓰는 말 |
|---|---|
| 길잡이 | 랜드마크 |
| 곧장, 왼쪽으로, 오른쪽으로 | 직진, 좌회전, 우회전 |
| 위치가 잘 안 잡혀요 | GPS가 부정확해요 |
| 체험하기 | 체험해 보기, 데모 |
| 사용 설명서 | 매뉴얼, 도움말 페이지 |
| 앱 열기 | 앱 열어 보기, 시작하기(소개 사이트) |
| 길을 자주 잃는 사람 | 길치 (화면에는 쓰지 않는다. 검색어에만 둔다) |
| 보호자 | 관리자, 담당자 |
| 다시 해 주세요 | 다시 시도해 주세요 |

## 이번 점검에서 고친 것 (2026-11-02)

- 홈 카드 설명이 하나는 "사진 찍기", 하나는 "만들어요"로 달라서 해요체로 맞춤
- 카드 수 "카드 4" → "카드 4장"
- "~를 누르세요" → 설명은 "눌러요", 부탁은 "눌러 주세요"
- 확인 창 기본 버튼 "취소" → "닫기"
- 길·카드를 못 찾을 때 할 일을 붙임
- 새 길 등록에서 AI가 안 될 때 "내일 다시 해 주세요. 메모로 카드를 만들었어요"처럼 안내가 서로 어긋나던 것 고침
- 서버 오류 "요청을 읽을 수 없어요", "사진이 없어요" → 할 일이 있는 문장으로
- 로드뷰 오류에서 '카카오 지도 파일 내용이 이상해요' 같은 개발 말 정리
- 설명서·체험·소개 사이트의 "GPS가 부정확" → "위치가 잘 안 잡혀요"
- 소개 사이트 설명에서 "길치" 뺌, "랜드마크 길안내" → "눈에 보이는 간판으로 안내"
- "체험해 보기 / 체험하기 / 2분 체험" → "체험하기"로 맞춤
- 퀴즈 오답 "정답은 꽃집." → "정답은 꽃집이에요."
- AI 지시문 말투 규칙을 하나(`TONE`)로 모으고 끝맺음·쉬운 말 규칙을 더함
- `lib/tone.ts`가 "좌회전하세요", "~할 것", "~하시기 바랍니다", "랜드마크"도 고침

## 두 번째 점검 (2026-11-04)

체험하기 첫 문장 "대전역 가는 길을 예로 들어, 길을 등록해서 걷는 과정을 처음부터 보여 줘요. 길을 잃었을 때 다시 찾는 방법도 나와요."를
기준으로 홈, 내 길, 처음 가는 길, 걷기, 길 찾기, 새 길 등록, 길잡이 바꾸기, 도움 요청, 설정, 설명서, 체험하기, 소개 사이트,
권한·음성·오류 문장을 다시 썼다. 끊긴 나열을 잇고, "출발지: 지금 위치"류 설명은 "지금 서 있는 곳에서 출발해요"처럼 풀었다.
